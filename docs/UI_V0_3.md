# v0.3.0 UI와 시설 데이터 설계

## 화면

지도는 같은 View 인스턴스를 유지하며 넓은 창에서는 약 60:40으로 지도와 안내 패널을 나란히 배치합니다. 세로 창에서는 지도 위·안내 아래로 전환하며 작은 창에서 최소 확인 영역을 확보합니다. 계획 화면은 지도 약 52%를 사용하며, 작은 세로 창의 하차 확인 단계는 확인 항목이 보이도록 안내 영역을 280dp(추가 도어 확인 시 340dp)까지 우선 확보합니다. 방향을 고정하거나 시스템 Driving view·GNB를 덮지 않습니다. 조건 선택은 정차 상태의 별도 시트에 모으고, 현재 단계의 주요 행동을 하단에 고정합니다.

라이트/다크/시스템 테마, 원본 벡터 아이콘, 큰 터치 영역, 제한된 단계 전환 애니메이션을 사용합니다. Kakao 지도 자체의 스타일은 SDK 기본값입니다. SDK 준비 콜백과 실제 타일 확인은 구분합니다.

## 추천 규칙

| 조건 | 시연 후보 선택 | 단계 |
|---|---|---|
| 부모님 또는 짧은 보행 | 가까운 입구·주차장·안내데스크 | 보호자 있으면 D → P → M |
| 아이·유모차 | 가족 입구·가족 주차장·가족 라운지 | 선택한 하차 방식 |
| 휠체어 또는 계단 없는 동선 | 무단차 연결을 설정한 가상 D4/P4/만남 공간 | 무단차 정보 누락이면 계획 보류 |
| 일반 동승자 | 중앙 입구·주차장·로비 | 선택한 하차 방식 |
| 운전자가 유일한 보호자 | 해당 조건의 주차장·만남 장소 | D 생략, P → M |
| 실제 서울아산병원 | 공식 대표 위치와 사실만 | D/P/M 검증 전 계획 보류 |

가상 접근성 정보는 실제 시설의 보증이 아닙니다. 장애인 전용 주차면 이용 자격은 휠체어 사용 여부만으로 판단하지 않습니다. 처음 확정한 만남 장소는 재합류까지 유지합니다.

## 실제 시설 근거

확인일: 2026-11-15. 출처는 서울아산병원 공식 사이트입니다.

- [오시는 길](https://www.amc.seoul.kr/asan/hospitalguide/location/location.do?by=subway3): 서울 송파구 올림픽로43길 88. 공식 페이지의 Google Maps 목적지 링크에서 대표 지점 `37.526922, 127.108381` 확인. 링크의 뷰포트 중심 좌표와 구별했습니다. 이 지점은 승하차장·차량 출입구가 아닙니다.
- [주차 안내](https://www.amc.seoul.kr/asan/hospitalguide/parkingguide/parkingGuide.do): 중앙주차장, 신관/동관 주차 관련 시설의 존재를 확인했습니다.
- 미확인: 승하차 허용 구역, 주차장 입구 좌표, 입구→승강기→목적 시설의 연속적인 무단차 동선, 만남 장소의 운영·접근 조건. 해당 정보를 만들어내거나 안전한 경로라고 단정하지 않습니다.

## Pleos 기준 적용

[레이아웃](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/layout), [타이포그래피](https://document.pleos.ai/docs/connect/guide/docs-design/foundations/typography), [색상](https://document.pleos.ai/docs/connect/guide/docs-design/foundations/colors), [애니메이션](https://document.pleos.ai/docs/connect/guide/docs-design/foundations/animation)을 참고했습니다. 공식 인증 또는 심사 통과를 의미하지 않습니다.

## v0.2.0 대비

- 고정 가상 시설 선택 → 공식 실제 시설 정보와 가상 시연의 분리.
- 기본 하차 방식 선택 → 보행·가족·무단차 조건에 따라 D/P/M 후보 변경.

- 하차 확인 직후 Mock 요청 → 다음 경로를 보여주고 별도 사용자 동의 후 요청.
- NaviHelper 조회 전용 → 권한·검증 좌표·연결을 확인하는 requestRoute 코드와 목적지 콜백 검증. 실제 요청 성공 검증은 별도.
- 도어 주기 조회 → 이벤트 구독 + 주기 조회 + 구독 해제·오래된 신호 방어.
- 기존 32개 단위 테스트 보존, 추천·동의·실제 목적지 방어 테스트 16개 추가.
